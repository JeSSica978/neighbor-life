## 开发环境启用与页面验收

开发库迁移前有 8 笔待支付历史订单，phase5 两列和 phase6 交易表尚不存在。停止已确认属于本项目的后端后，执行 `tools/Invoke-BusinessMigration.ps1 -Action Migrate`，增量建表、补索引、迁入真实点赞/关注关系和商品规则，没有重导初始化库。

完整本机备份位于 `backups/development-business-migration-20261125-152737/`，含迁移前 SQL 和历史订单字段快照；目录设置了本机访问 ACL，并被 Git 忽略。迁移后及临时数据清理后，两次对比确认原有 8 笔订单的 ID、归属、状态、支付方式和创建/支付/使用/退款时间完全相同。旧订单没有新增 `tb_order_detail`，仍不进入生命周期任务。

开发环境冒烟发现旧店铺表 `sold/comments/score` 无默认值；此前测试直接用 SQL 建 fixture 没覆盖真实建店入口。已修正 `CatalogService.saveShop` 的服务端初始化，并让独立验收通过真实建店 API 创建 fixture，随后复测通过。

使用临时新账号、新店铺、新券进行开发环境验证：2 笔普通券订单都完成模拟支付并各发 1 张券，1 笔所属商家核销后通过页面评价，另 1 笔通过页面退款；1 笔秒杀经 Kafka 落库后取消。Redis 与 DB 的秒杀库存最终都为 `3`，`RELEASE` 账目为 `1`，相关待处理事件为 `0`。

页面实际操作确认：订单中心显示“已退款”，核销订单可以提交评价，店铺详情显示新评价、评分和券真实库存。截图：`refund-page.jpg`、`review-page.jpg`。

清理前 Kafka 消费记录为秒杀 offset `8/8, lag=0`、返库 offset `1/1, lag=0`，缓存主题无消息（同步提交后已完成失效）。随后停止后端，仅删除本次临时账号、店铺、券、订单、支付、退款、核销、评价、事件和相关 Redis 数据。所有开发表行数恢复到迁移后冒烟前数量；Kafka 主题及 offset 保留。临时授权一并撤销，没有替真实账号推断商家/管理员身份。
