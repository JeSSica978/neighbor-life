## 项目及边界

项目路径：`D:\Development\neighbor-life`。NeighborLife（邻享生活）基于黑马点评后端，当前前端为 Spring Boot 提供的静态页面，主要逻辑在 `src/main/resources/static/assets/app.js`。根项目使用 JDK 11、Spring Boot 2.3.12、MyBatis-Plus、MySQL、Redis、Kafka；`com.hmdp` 包名、数据库 hmdp、原有业务协议保留。

所有已有 Git 暂存、未暂存和未跟踪修改保留，没有提交或 Push。没有执行 JMeter 压测、真实支付、AI consultant 集成、Redis 全库清理或数据库重建。独立测试数据均限定归属；测试不回退共享 ID 序列。

1. **启动和调试环境**：完成本地 Docker MySQL/Redis/Kafka、后端与静态前端启动检查，补充 VS Code JDK/Maven/F5 配置及普通 Run 任务。阶段二真实 HTTP 断点通过。F5 是调试运行；Ctrl+Shift+B 或 `tools/Invoke-NeighborLife.ps1 -Action Run` 是普通运行。服务默认端口 8081，不需要另外启动前端。
2. **前后端审计**：按实际代码建立登录、身份、店铺列表/详情/分类/搜索、笔记、点赞、收藏、优惠券映射。登录从 MySQL 用户和 Redis token 验证身份；店铺 1 的真实详情返回 `success=true`、`data.id=1`、`data.name=103茶餐厅`。断点暂停超过前端 12 秒请求超时后，再按 F5 不能恢复已取消请求，需要重新发起。
3. **秒杀链路恢复**：处理消费者未注册和消息类型不匹配。统一 Kafka JSON 字符串及字符串订单 ID；Lua 原子预扣库存、记录用户资格、reservation 和 outbox Stream；Publisher 收到 Broker ack 后删除 outbox，发送失败保留同一订单 ID 重试；Consumer 经 Spring 事务代理执行 MySQL 券行锁、库存更新和订单插入，重复消息幂等。事务返回后完成 Redis 状态，最后确认 Kafka offset，消费失败保留消息重试。
4. **秒杀真实验证**：通过 Lua 0/1/2/3/4、实际消息发送和消费、待支付订单落库、重复下单、售罄、重复消息不重复插单/扣库存、INSERT 失败回滚和恢复、Producer 不可达恢复、Consumer 停止恢复、3 个独立用户竞争 2 份库存。使用真实 HTTP、MySQL、Redis、Kafka；不是压测或真实付款。
