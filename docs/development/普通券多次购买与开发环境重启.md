# 普通券多次购买与开发环境重启

2026-11-25，Asia/Shanghai。操作目录为 `D:\Development\neighbor-life`。

## 普通券购买规则

普通券可以多次购买，每次点击购买一张，新购买创建新订单。取消或模拟支付后也能继续购买。浏览器在一次购买失败时保留请求编号，重试使用相同的 `Idempotency-Key`，避免网络超时导致重复订单；收到成功订单编号后，下次购买使用新编号。已有订单均保留。

秒杀券仍每人每券一单。数据库把原来的全局 `(user_id,voucher_id)` 唯一约束换成 `(user_id,seckill_voucher_id)`：只有秒杀订单写入这个字段，普通订单为 NULL。同时 `(user_id,request_id)` 唯一约束保障普通券请求幂等。普通券不使用秒杀库存和 Kafka 下单链路。

迁移文件是 `src/main/resources/db/migration/phase5-normal-voucher-repurchase.sql`。迁移前新后端会提示 `NORMAL_REPURCHASE_SCHEMA_REQUIRED`，普通券购买接口会提示需迁移，旧订单查询仍可用。

## 选择开发环境

本项目原开发配置是根目录 `src/main/resources/application.yaml`，使用 Spring 的 `default` 配置；没有新增 `application-dev.yml`。

| 环境 | Spring 配置 | HTTP | MySQL | Redis | Kafka |
| --- | --- | --- | --- | --- | --- |
| 日常开发 | default / application.yaml | 8081 | 3306 / hmdp | 6379 | 9092 |
| 独立测试 | loadtest / application-loadtest.yml | 8082（JUnit 随机端口） | 3307 / hmdp_loadtest | 6380 | 9093 |

在 VS Code 打开 `D:\Development\neighbor-life`，按 **Ctrl+Shift+D**，在上方配置下拉框选择 **NeighborLife: Development (JDK 11)**，按 **F5** 调试。此配置明确指定 `default` 和 8081。普通运行可按 **Ctrl+Shift+B**，调用 **NeighborLife: Run Backend (Maven)**；启动脚本也明确指定 `default`。

不要同时启动 Maven 和 F5 两个后端。F5 调试结束可按 Shift+F5；Maven 前台运行可按 Ctrl+C。

## 首次启用前先处理数据库

2026-11-25 只读核对时，开发库已有 8 笔状态为 1 的订单，尚无 `tb_reliable_event` 和 `idx_order_status_create`；普通券多次购买迁移也未执行。先确定历史订单处理方式，再启用生命周期功能。默认支付期限为 900 秒，自动扫描、查询订单和订单列表都可能关闭超时待支付订单。店铺 18 / 券 26、27、28 的历史保护要求见阶段四报告。

如果希望保留旧订单而只对新订单自动关单，先不要启用阶段四，现代码尚无按订单创建起始时间限定处理范围的开关。单纯延长扫描间隔也不能阻止查询订单时被动关单。

1. 停止后端，Docker 中间件继续运行：

   ```powershell
   Set-Location D:\Development\neighbor-life
   .\tools\Invoke-NeighborLife.ps1 -Action Stop
   ```

2. 在 MySQL 客户端选择 `127.0.0.1:3306` 的 **hmdp** 数据库，执行只读核对：

   ```sql
   SELECT DATABASE();
   SHOW INDEX FROM tb_voucher_order;
   SELECT id,voucher_id,status,create_time
   FROM tb_voucher_order WHERE status=1 ORDER BY create_time,id;
   SELECT id,voucher_id,create_time FROM tb_voucher_order
   WHERE status=1 AND create_time<=TIMESTAMPADD(SECOND,-900,CURRENT_TIMESTAMP);
   SELECT o.id,o.voucher_id FROM tb_voucher_order o
   LEFT JOIN tb_voucher v ON v.id=o.voucher_id
   WHERE v.id IS NULL OR v.type NOT IN (0,1);
   ```

   最后一条必须没有记录。若有缺失/未知类型的券，先核对历史订单对应类型，不能跳过回填秒杀约束。

3. 备份开发数据库。以下命令复用已有容器内部凭据，备份文件放在仓库外：

   ```powershell
   $devBackupDir = 'D:\Development\neighbor-life-backups'
   New-Item -ItemType Directory -Path $devBackupDir -Force | Out-Null
   $devBackupFile = Join-Path $devBackupDir ('hmdp-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.sql')
   docker exec neighborlife-dev-mysql-1 sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysqldump -u root --single-transaction --no-tablespaces hmdp' |
     Set-Content -LiteralPath $devBackupFile -Encoding UTF8
   if ($LASTEXITCODE -ne 0) { throw '数据库备份失败，请停止迁移。' }
   Get-Item -LiteralPath $devBackupFile | Select-Object FullName,Length
   ```

4. 核对现有结构与迁移文件，确认备份成功及历史订单处理范围后，各执行一次。两份迁移均不能盲目重复执行，也不要导入初始化 `hmdp.sql`：

   ```powershell
   Get-Content .\src\main\resources\db\migration\phase4-order-lifecycle-and-reliable-events.sql -Raw |
     docker exec -i neighborlife-dev-mysql-1 sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -u root hmdp'
   if ($LASTEXITCODE -ne 0) { throw '阶段四迁移失败，请先核对结构。' }

   Get-Content .\src\main\resources\db\migration\phase5-normal-voucher-repurchase.sql -Raw |
     docker exec -i neighborlife-dev-mysql-1 sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -u root hmdp'
   if ($LASTEXITCODE -ne 0) { throw '普通券迁移失败，请先核对结构。' }
   ```

   若某个表、列或索引已经存在，先检查迁移完成到哪一步；DDL 不会整体事务回滚。阶段五只有在新约束和历史秒杀回填成功后，才移除原全局唯一索引。

## 重启后端

迁移及历史订单核对完成后，在新的 PowerShell 终端执行：

```powershell
Set-Location D:\Development\neighbor-life
# 明确使用开发配置和默认端口，清除独立测试/外部配置的覆盖。
Remove-Item Env:SPRING_PROFILES_ACTIVE,Env:SPRING_CONFIG_LOCATION,Env:SPRING_CONFIG_ADDITIONAL_LOCATION,Env:SPRING_DATASOURCE_URL,Env:SPRING_REDIS_URL,Env:SPRING_REDIS_HOST,Env:SPRING_REDIS_PORT,Env:SPRING_KAFKA_BOOTSTRAP_SERVERS -ErrorAction SilentlyContinue
$env:SERVER_PORT = '8081'
.\tools\Invoke-NeighborLife.ps1 -Action Run
```

启动脚本会检查端口、启动开发 Docker 中间件、使用 JDK 11 和已有 Maven 运行根项目。看到 `Started HmDianPingApplication` 后，打开 `http://localhost:8081`；浏览器按 **Ctrl+F5** 更新页面脚本。

若日志出现 `ORDER_LIFECYCLE_SCHEMA_REQUIRED`，阶段四结构检查未通过；若出现 `NORMAL_REPURCHASE_SCHEMA_REQUIRED`，阶段五结构检查未通过。重新检查正确数据库的结构，完成后再重启。仅刷新浏览器不能加载新的 Java 后端代码或完成数据库迁移。

验证普通券连续购买两次得到不同订单编号，两个订单都出现在订单中心；点击一次购买后发生网络错误，重试应返回同一订单。模拟支付不扣款。秒杀重复购买仍返回“重复下单”。

店铺编辑演示默认关闭；要测试缓存补偿页面，还需配置 `hmdp.demo.shop-edit-enabled=true` 和明确的 `hmdp.demo.shop-ids` 白名单。后端提交后删缓存及补偿链路会在阶段四结构通过检查后启用。
